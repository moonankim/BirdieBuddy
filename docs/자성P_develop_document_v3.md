- 화면은 루트 단일 Next.js 앱이고 실제 Supabase 로그인과 SDK(`lib/api`)로 동작한다. `NEXT_PUBLIC_DATA_MODE=mock`이면 목 SDK로 동작한다.

## 3. R-1 "여기까지 읽었어요"

### 3.1 PRD 요구 요약(4절)

- 읽음 기준: 방·인박스를 열면 그때까지 받은 것과 열어 둔 동안 실시간으로 받은 것을 모두 읽음으로 본다. 화면 노출 추적은 없다. 팬이 메시지를 보내면 그 시점까지 읽음. 내 메시지는 안 읽은 수에 넣지 않는다.
- 팬 채팅방: 첫 안 읽은 메시지 바로 위에 "여기까지 읽었어요" 구분선, 그 위치에서 연다. 최신 50개 밖이면 그 위치부터 불러온다. 안 읽은 게 없으면 구분선 없이 최신에서 연다. 구분선은 방에 있는 동안 유지, 다시 들어와 새 메시지가 없으면 사라진다.
- 최신 메시지로 이동: 구분선 위치에서 열었고 최신 메시지가 화면 밖이면 "최신 메시지로 ↓" 버튼(개수 표시 없음).
- 채팅방 목록: 방마다 안 읽은 수, 100건 이상은 "99+". 하단 메뉴에는 표시하지 않는다.
- 인플루언서 인박스: 정렬은 그대로, 지난 인박스 확인 뒤 들어온 질문 카드에 "NEW", 상단에 "지난 확인 이후 새 질문 N건". 묶음은 새 질문이 하나라도 있으면 NEW. 재입장 팬 질문의 재노출과 답변 완료 항목은 NEW 아님.
- 예외: 첫 입장은 구분선 없음. 퇴장 중 달린 내 질문의 답변은 재입장 뒤 안 읽음으로 세고 퇴장 전 읽은 위치를 쓴다. 삭제된 메시지는 안 읽은 수에서 빼고, 첫 안 읽은 메시지였으면 그다음 메시지 위에 구분선.
- 실패: 읽은 위치를 정하는 동안은 메시지 목록 대신 로딩. 불러오지 못하면 구분선 없이 최신에서 열고 목록 숫자·인박스 NEW를 숨긴다. 채팅방·인박스는 평소대로 쓸 수 있어야 한다.
- 범위 밖: 안 읽음으로 표시하기, 상대에게 보이는 읽음 확인.

### 3.2 필요한 서버 기능(홍주P에게 제안, 최종 형태는 홍주P 결정)

메시지 ID는 방 안에서 증가하는 bigint(문자열)라 "마지막으로 읽은 메시지 ID" 하나로 계산할 수 있다.

| 제안 SDK 함수 | 입력 | 출력 | 비고 |
| --- | --- | --- | --- |
| `getRoomReadState` | `{ roomId }` | `{ lastReadMessageId: MessageId \| null, firstUnreadMessageId: MessageId \| null, unreadCount: number }` | 팬 본인. 삭제·내 메시지 제외, 퇴장 중 내 질문 답변 포함 |
| `markRoomRead` | `{ roomId, lastReadMessageId }` | `{ lastReadMessageId }` | 서버가 기존 값보다 클 때만 갱신(되돌아가지 않음). 같은 값 반복 호출 허용 |
| `getRooms` 항목에 `unreadCount: number \| null` 추가 | — | — | 조회 실패·미입장은 `null`로 숨김 |
| `getInboxReadState` | `{ roomId }` | `{ lastCheckedMessageId: MessageId \| null }` | 방 소유 인플루언서 |
| `markInboxChecked` | `{ roomId, lastCheckedMessageId }` | 같음 | 서버가 큰 값만 저장 |
| `InboxItem.isNew: boolean`, `InboxPage.newCount: number` | — | — | 재입장 재노출·답변 완료 제외 규칙은 서버 판정 권장 |

화면은 위 함수가 없을 때(목 모드 또는 서버 미구현) 실패 경로(구분선·숫자·NEW 숨김)로 동작해야 한다.

**구현 현황(2026-11-13, main `da1a6dd`):** 홍주P B-18이 main에 병합됐다(`4b1f664`, migration `20261113011530_read_state_checkpoints.sql`). 원격 DB 적용과 런타임 검증은 아직이다. 실제 계약(`lib/api/types.ts`):

| 함수·필드 | 형태 |
| --- | --- |
| `getRoomReadState({ roomId })` | `RoomReadState { lastReadMessageId, firstUnreadMessageId, unreadCount }` |
| `markRoomRead({ roomId, lastReadMessageId })` | `{ lastReadMessageId }` |
| `getRooms` 항목 | `unreadCount: number \| null` |
| `getInboxReadState({ roomId })` | `InboxReadState { roomId, lastCheckedMessageId }` |
| `markInboxChecked({ roomId, lastCheckedMessageId })` | `{ lastCheckedMessageId }`. 새로 앞으로 옮길 때는 지금 입장 기간의 통과 질문까지만 허용 |
| `InboxItem.isNew`, `InboxPage.newCount`·`checkedThroughMessageId` | 인박스 조회가 읽음 상태를 함께 준다 |

목 SDK에는 아직 기본값(`unreadCount: null`, `isNew: false`, `newCount: 0`)만 들어가 있고 위 함수는 없다. `ChatApi`(`components/chat/api/chat-api.tsx`)에도 읽음 함수가 빠져 있으므로 R-1에서 둘 다 추가한다.

### 3.3 화면 동작

**팬 채팅방 `/chat/[roomId]`**

1. 입장 상태 확인 뒤 `getRoomReadState` → 결과가 오기 전에는 메시지 목록 자리에 로딩만 보인다.
2. `firstUnreadMessageId`가 없으면 지금처럼 최신 50개에서 연다(구분선 없음).
3. 있으면 첫 화면 범위를 정한다.
   - 최신 50개 안이면 지금처럼 불러오고 그 메시지 위에 구분선.
   - 50개 밖이면 `getMessages({ roomId, afterId: lastReadMessageId, limit: 50 })`로 첫 안 읽은 메시지부터 불러오고, 위쪽은 "이전 메시지 더 보기", 아래쪽 남은 메시지는 스크롤 끝에서 이어 불러온다.
4. 구분선으로 스크롤해 열고, 최신 메시지가 화면 밖이면 "최신 메시지로 ↓" 버튼을 띄운다. 맨 아래가 보이면 숨긴다(IntersectionObserver).
5. 구분선 위치는 진입 때 한 번 정하고 방에 있는 동안 고정한다. 삭제된 첫 안 읽은 메시지는 건너뛴다.
6. 읽음 저장(`markRoomRead`): 진입해 메시지를 받은 직후, 열어 둔 동안 실시간 메시지를 받을 때, 내가 메시지를 보낼 때. 짧은 간격으로 묶어 보내고 실패는 조용히 다음 기회에 다시 보낸다.
7. 첫 입장(인사말만 있는 상태)은 구분선 없음.
8. `use-room-messages`에 "처음 불러올 위치" 인자를 추가하고 기존 실시간·복구(checkpoint)·삭제 처리는 그대로 둔다.

**채팅방 목록 `/chat`**: 방 카드에 안 읽은 수 배지(1~99, 100 이상 "99+"). 0이거나 `null`이면 숨김. 하단 바에는 표시하지 않는다.

**인박스 `/inbox`**: 진입 때 `getInboxReadState`와 목록을 함께 읽는다. `isNew` 항목에 NEW 배지, 상단에 "지난 확인 이후 새 질문 N건". 목록을 받은 뒤 `markInboxChecked`로 이번 목록의 가장 큰 질문 ID를 저장한다. NEW 표시는 인박스에 있는 동안 유지하고, 다시 열면 그 사이 들어온 것만 NEW다. 실패하면 NEW·건수를 숨긴다.

### 3.4 목 SDK

같은 함수를 목 SDK에 먼저 만든다. 계정·방별 마지막 읽은 ID를 기억하고, 삭제·내 메시지 제외, 첫 입장 구분선 없음, 재입장 답변 포함, 인박스 재노출 제외 규칙을 흉내 낸다. 실제 함수가 나오면 `ChatApi`에 이름을 추가하고 타입은 `lib/api/types.ts`를 따른다(목 쪽에 타입을 복제하지 않는다).

### 3.5 디자인(현호P에게 요청)

구분선, 안 읽은 수 배지, NEW 배지, "최신 메시지로 ↓" 버튼의 시안. 시안 전에는 디자인 시스템 토큰(`badge`, 구분선은 `--border` 계열, 버튼은 `bb-button` 보조형)으로 임시 표시하고, 시안이 오면 클래스만 바꾼다.

### 3.6 테스트(vitest)

- 목 SDK: 읽음 위치 갱신은 커지는 방향만, 삭제·내 메시지 제외, 첫 입장 0건, 재입장 답변 포함, 인박스 NEW 판정.
- 채팅방: 구분선 위치·50개 밖 진입 범위·구분선 고정·최신 이동 버튼 표시/숨김·전송 시 읽음 저장·실패 시 최신에서 열기.
- 목록: 1·99·100(99+)·0/null 숨김.
- 인박스: NEW·상단 건수·정렬 유지·확인 저장·실패 시 숨김.

### 3.7 완료 기준

목 모드에서 위 동작과 테스트 통과, 실제 모드에서 서버 함수가 없으면 실패 경로로 평소처럼 동작. 서버 함수가 생기면 실제 데이터로 두 계정(팬·인플루언서) 확인.

## 4. D-1 디자인 시스템 0.4 점검

- 채팅·인박스·설정·인증·관리자·로그인을 새 색(아이보리·딥그린)에서 한 번씩 확인하고, 화면에 직접 넣은 예전 색·임시 클래스가 있으면 공통 클래스로 바꾼다.
- `AGENT_GUIDE.md`에서 "실제 연결은 별도"로 남긴 항목 중 화면 담당 몫을 연결한다: 공통 로딩(스피너)·오류·404 레이아웃, 기본 프로필 이미지(`public/assets/avatar-default.svg`)를 Avatar 대체 표시로(현재는 이름 첫 글자). 카드 일러스트 대체는 C-1 이후.
- 예전 목업용 스타일(`card-picture`·`portrait` 등) 중 더 쓰지 않는 것은 현호P와 확인 후 정리.
- **토큰 값 변경 확인(PR #35):** 채팅·인박스·설정·관리자에서 바탕·테두리·보조 글자·비활성 색이 아이보리 톤으로 바뀌었다. 대비·읽기 어려운 곳을 확인한다. 홈의 기존 rare 배지가 새 RARE 평행사변형(레드)으로 보이는지도 확인한다.
- **카드 디자인 2차 적용(합의 후):** `AGENT_GUIDE.md` "카드 기반 디자인 시스템 2차 적용" 대응표를 따른다. 글 위주 화면에 포스터 제목·사선 띠·골드를 쓰지 않고, 등급 레드(`--grade-rare-*`)를 오류 색으로 쓰지 않는다. 등급 배지는 새 3등급 SDK 전환 뒤에만 적용한다.

## 5. 대기 작업

- **A-1 관리자 데모 월(이제 가능):** `getAdminDemoMonth()`는 main에 있고 `ChatApi`·목 SDK에도 홍주P가 추가해 두었다. 관리자 화면 시작 시 이 값으로 현재 월 표시·다음 달 계산을 하고, 실패하면 KST 이번 달을 쓰지 말고 오류·재시도를 보여 준다(8.2). 원격 DB 적용 전에는 실제 모드에서 오류가 뜨는 것이 정상이다.
- **C-1 카드 실제 데이터:** `card-ui-handoff.md`(목록 표시 규칙·API 연결 시 교체 지점)대로 현호P의 구성요소를 재사용한다. `/collection` 정적 도감(`CardCatalog`)은 `ownership`에 보유 수량만, `/collection/owned`(`CardCollection`)는 `templates`·`status`·`onRetry`에 실제 조회 결과를 넣는다. 목업을 실제 수량의 대체값으로 쓰지 않는다. 강화는 `upgradeCard`(같은 요청 ID 재시도) 뒤 목록 재조회. 계정 전환·새로고침·오류·미보유 상태 확인.
- **H-1 홈·발급 결과:** 새 규격이 오면 `app/(user)/_lib/cards.ts`의 등급·스타일 표시를 새 규격(4유형·3등급)으로 바꾸고 상세 링크(`/collection/[cardId]`)를 연결한다.
- **DEP-1 배포:** 빌드 루트를 레포 루트로, `npm run build`(webpack). 환경 변수는 공개 Supabase URL·키만. 배포 주소를 홍주P에게 알려 허용 출처·Auth 리디렉트에 추가.
