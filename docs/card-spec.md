# 카드 기준 변경과 담당자 인계

**기준일:** 2026-11-12

**근거:** 현호P 사용자 확정 — 현재 제작된 카드에는 디자인 스타일 구분이 없고, 유형은 `kpga`, `klpga`, `gtour`, `media`, 등급은 `basic`, `rare`, `legend`입니다.

## 확정된 제품 기준

| 항목 | 최신 기준 | 이전 구현·계획 |
| --- | --- | --- |
| 디자인 스타일 | 없음. 스타일 선택·필터·수집 축을 두지 않음 | `illust / retro / holo` |
| 카드 유형 | `kpga / klpga / gtour / media` | `youtuber / media_pro / tour` |
| 카드 등급 | `basic / rare / legend` 순의 3등급 | `common / rare / epic / special` 4등급 |
| 최종 카드 path | `<유형>-<선수명>-<레벨>.png` · 유형·레벨 소문자 · PNG | `<UUID>/<style>.webp` |
| 표시명 | KPGA / KLPGA / G투어 / 미디어, BASIC / RARE / LEGEND | 기존 화면의 일반·레어·에픽·스페셜 |

카드는 인물·카드 유형·등급으로 설명하며 스타일을 별도 속성으로 요구하지 않습니다. 카드 템플릿의 DB 식별 키와 유형·인물의 관계는 백엔드 계약 변경 시 확정합니다. 유형 4개를 스타일이나 등급으로 취급하지 않습니다.

이 문서는 PRD의 최신 카드 변경 명세입니다. PRD·담당 계획·용어집·디자인 가이드의 기존 카드 정의와 충돌하면 이 문서를 우선합니다. 이전 10명×3스타일·30종·4등급 수치는 기존 구현 설명이며 신규 요구사항으로 복제하지 않습니다.

## 최종 카드 path·파일 규칙

사용자 확정 규칙은 **`<유형>-<선수명>-<레벨>.png`**입니다. 여기서 레벨은 카드 등급과 같은 의미이며 별도 숫자 레벨을 추가하지 않습니다.

- 유형: `kpga`, `klpga`, `gtour`, `media`
- 레벨: `basic`, `rare`, `legend`
- 유형·선수명·레벨 순서로 하이픈으로 구분합니다. 유형과 레벨은 소문자 영문, 확장자는 `.png`, MIME은 `image/png`를 사용합니다. 선수명은 [실제 CDN 목록](./card-assets.md)의 `playerSlug`를 그대로 사용합니다. 밑줄·하이픈을 임의 변환하지 않습니다. 파일의 실제 인코딩도 PNG여야 합니다.
- 예: `gtour-gong_tae_pung-basic.png`, `gtour-gong_tae_pung-rare.png`, `gtour-gong_tae_pung-legend.png`. 실제 업로드 주소를 기준으로 합니다.
- 선수명은 필수입니다. 스타일 문자열, UUID, `design-3` 같은 제작 버전 접미사를 최종 path에 임의로 추가하지 않습니다. 이전에 제안한 `<유형>/<UUID>/<등급>.webp`도 확정 규칙이 아닙니다.
- 최종 아트는 Supabase Storage가 아니라 사용자가 제공한 **R2 CDN**에 있습니다. [실제 CDN 목록·DB/프론트 연결 지침](./card-assets.md)과 [JSON manifest](./assets/card-images.json)를 따릅니다. DB에 상대 path를 저장하는 경우 R2 base URL로 해석하며 기존 Supabase `getPublicUrl`을 적용하지 않습니다. 등급별 경로 저장 구조와 실제 반영은 홍주P의 계약 전환 작업입니다.

| 유형 | BASIC | RARE | LEGEND |
| --- | --- | --- | --- |
| KPGA | `kpga-<선수명>-basic.png` | `kpga-<선수명>-rare.png` | `kpga-<선수명>-legend.png` |
| KLPGA | `klpga-<선수명>-basic.png` | `klpga-<선수명>-rare.png` | `klpga-<선수명>-legend.png` |
| G투어 | `gtour-<선수명>-basic.png` | `gtour-<선수명>-rare.png` | `gtour-<선수명>-legend.png` |
| 미디어 | `media-<선수명>-basic.png` | `media-<선수명>-rare.png` | `media-<선수명>-legend.png` |

위 표는 일반 경로 형식이며, 실제 전달된 36개 주소는 CDN manifest를 기준으로 합니다. 유형 뒤의 선수명으로 서로 다른 인물을 구분합니다. 유형·선수명·레벨 전체 조합이 중복되거나 동명이인이 있으면 업로드 전에 인물별 리소스 연결 방식을 확인합니다. 에이전트는 임의의 하위 폴더 규칙을 만들거나 기존 이미지를 덮어쓰지 않습니다.

## 현재 구현과의 차이

이번 변경은 문서 인계이며 DB·RPC·SDK·UI·시드·이미지 업로드·원격 배포를 변경한 것이 아닙니다. `lib/api/types.ts`, DB enum과 카드 조회·발급·강화는 기존 스타일·4등급 계약을 사용합니다. `components/ui/card-artwork.tsx`, 목업, 배지와 정적 샘플에도 이전 등급이 남아 있습니다. 각 담당자는 실제 코드와 대조해 전환 완료 여부를 확인해야 합니다.

기존 `InfluencerType`은 인증·프로필·채팅 계약에서도 사용합니다. 카드 유형 변경을 이유로 계정 역할이나 인증 유형까지 자동 치환하지 않습니다. 공용 필드 변경 여부와 카드 전용 유형 분리는 홍주P·자성P가 계약으로 합의합니다.

### 2026-11-13 홍주P 백엔드 코드 대조

main PR #30/#32 병합 후에도 백엔드 전환은 시작되지 않았습니다. `supabase/migrations/20261111063044_core_schema.sql`은 `card_style (illust/retro/holo)`, `card_grade (common/rare/epic/special)`, `card_templates`의 `(influencer_id, style)` 고유 키와 `<UUID>/<style>.webp` 제약을 정의합니다. RPC·seed·SDK도 기존 등급·이미지 경로를 사용합니다. `/home`·`/draw`가 호출하는 API는 이 구형 계약이고 `/collection/**`는 새 제품 규격을 보여 주는 목업입니다. R2 manifest는 제공됐지만 DB 매핑과 SDK URL 연결은 아직 없습니다.

홍주P가 다음에 진행할 백엔드 작업은 새 카드 전용 유형·인물 key·등급별 이미지 경로·보유 조회·발급/강화 RPC와 seed/config의 migration 설계입니다. 이 변경은 `influencer_type`을 바꾸지 않고 기존 계정·채팅 검증 계약과 분리합니다. migration과 데이터 이관을 확정하기 전에 manifest의 12개 `playerSlug`↔DB 인물 UUID 매핑, 기존 4→3등급 데이터 처리, 3등급 확률, 스타일 기반 점수·배지·입장 기준의 대체 규칙을 담당자와 정합니다. 현재 정보만으로 이 값을 추정해 migration이나 hosted 데이터를 바꾸지 않습니다.

## 담당자별 반영 사항

| 담당 | 할 일 |
| --- | --- |
| 현호P | 제작 카드의 인물·유형·등급·파일 목록을 정리하고 누락을 검수. 상세·강화·공개 연출과 배지를 새 3등급 기준으로 설계. 스타일 선택·필터 제거. `<유형>-<선수명>-<레벨>.png` 제작 목록과 PNG 실파일 검수 |
| 홍주P | enum·카드 템플릿 키·보유 수량·RPC·SDK·Storage 경로·시드 변경안 작성. 기존 데이터 보존·이관과 구버전 클라이언트 영향 확인. `image_path`·업로드·시드를 `<유형>-<선수명>-<레벨>.png`로 전환하고 경로 충돌 검수 |
| 문환P | 발급 등급·확률 설정·강제 등급·회귀 테스트를 3등급 계약에 맞춤. 스타일 기반 추첨과 점수·보유 배지 영향 검토. 응답 이미지 path에 스타일·WebP 경로를 재생성하지 않음 |
| 자성P | 유형·등급 필터, 카드 정보·수량·강화 진입·발급 결과·관리자 데모 UI를 새 SDK 계약에 연결. 디자인 시스템·에셋 연동. SDK의 PNG URL을 사용하고 스타일 기반 파일명 조합 제거 |

## 아직 확정하지 않은 항목

- 전달된 CDN 에셋은 선수 식별자 12개 × 3등급 = 36개입니다. DB 인물 UUID·템플릿 매핑과 발급 라인업은 이 목록과 대조해 확정합니다. 기존 30장을 목표로 삼지 않습니다.
- 3등급 발급 확률: 기존 70/20/7.5/2.5%를 임의로 합치거나 재분배하지 않습니다.
- 데이터 이관: `common → basic`, `epic/special → legend` 같은 자동 매핑은 확정 사항이 아닙니다.
- 강화: 새 등급 순서는 BASIC → RARE → LEGEND, 최고 등급은 LEGEND입니다. 기존 비용·성공 규칙을 이번 요청으로 변경하지 않으며 적용할 서버 설정·데이터 이관을 확인합니다.
- 이미지: path와 PNG 포맷은 위 규칙으로 확정되었습니다. 인물별 연결과 동일 유형·선수명·레벨 경로 충돌 여부는 제작 목록과 대조해 확인합니다. 기존 `<UUID>/<style>.webp`를 신규 파일 규격으로 사용하지 않습니다.
- 스타일 수집에 따른 추가 점수·배지·입장 조건: 스타일 제거 후 대체 계산을 임의로 정하지 않습니다.

## 적용·검증 순서

1. 현호P 제작 목록과 백엔드 데이터 모델·SDK 변경 계약을 합의합니다.
2. 확률·이관·인물별 이미지 연결과 경로 충돌 처리·스타일 의존 규칙을 확정합니다.
3. 백엔드·발급·화면·에셋을 같은 계약으로 전환합니다.
4. 3등급 발급·최고 등급 강화 거부·유형 필터·수량·이미지 실패와 기존 계정·카드 데이터 보존을 검증한 뒤 배포합니다.
