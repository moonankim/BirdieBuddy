# BirdieBuddy 앱 디자인 가이드

> **카드 UI 후속 인계:** [목록·상세·강화 변경과 담당자별 연결 사항](./card-ui-handoff.md)을 먼저 확인합니다. 사용자 지시로 이번 단계의 API 연결은 제외했습니다. 장수·수집 현황·강화 결과는 목업이며 실제 데이터나 서버 성공으로 취급하지 않습니다.

> **실제 카드 이미지 인계:** [R2 CDN 주소·DB/프론트 적용 지침](./card-assets.md), [36개 이미지 JSON 목록](./assets/card-images.json)을 사용합니다. 선수 식별자 12개·3등급이며 최종 이미지는 R2 출처입니다. 기존 Supabase Storage URL 생성·스타일 기반 경로를 그대로 적용하지 않습니다. DB·SDK·화면 연결은 아직 별도 작업입니다.

> **디자인 시스템 적용 인계:** 화면·공통 UI 작업 전 [에이전트 적용 가이드](../design-system/AGENT_GUIDE.md)를 확인합니다. 최신 원본·적용 상태·샘플 전용 구성·담당 경계와 검증 기준을 정리했습니다. 실제 API 연결을 보존하고 이전 카드 정의를 신규 요구사항으로 복제하지 않습니다.

**기준일:** 2026-11-12

**상태:** 디자인 시스템 0.4 기반 구현 가이드. 카드 뽑기 연출은 2026-11-13 확정(`/draw/preview` 시안), 최종 카드 디자인은 미확정입니다.

실제 개발용 토큰·스타일·아이콘과 React 구성요소는 [개발 적용 가이드](../design-system/DEVELOPMENT.md)를 따릅니다. 앱은 `tokens.css`와 `app.css`를 직접 참조하며, 기존 프론트 CSS에는 이전 화면의 호환 스타일이 남아 있습니다. 새 구성요소는 공통 원본에 추가합니다.

## 최신 카드 기준

[카드 변경 명세](./card-spec.md)에 따라 스타일 구분 없이 KPGA·KLPGA·G투어·미디어 4유형과 BASIC·RARE·LEGEND 3등급을 사용합니다. 최종 카드 path는 `<유형>-<선수명>-<레벨>.png`이며 실제 PNG 이미지를 사용합니다. 예: `kpga-<선수명>-basic.png`, `gtour-<선수명>-legend.png`. 카드 화면의 UI 타입·배지와 시안의 컬렉션·추가 화면은 3등급으로 바꿨습니다. 실제 SDK 계약·이미지 매핑 전환은 미완료입니다.

## 기준과 적용 범위

앱 전반의 화면은 [`design-system/`](../design-system/README.md)의 아이보리 배경, 딥그린 주요 버튼, 절제된 테두리와 모서리과 모바일 중심 레이아웃을 공통 기준으로 사용합니다. 제품 동작은 [PRD](./prd.md), 데이터와 권한은 [아키텍처](./architecture.md) 및 담당 계획을 따릅니다. 디자인 시스템의 HTML은 정적 시안이며 기능 구현이나 검증 완료를 뜻하지 않습니다.

원본 토큰과 구성은 [`styles.css`](../design-system/styles.css), 컴포넌트 예시는 [`index.html`](../design-system/index.html), 홈·컬렉션·채팅은 [`sample/`](../design-system/sample/index.html)을 참고합니다. 현재 프론트의 [`design-system.css`](../app/design-system.css)는 기존 화면의 호환 스타일입니다. 색상·간격은 `tokens.css`, 카드 중심 구성은 `club.css`를 앱과 시안에서 직접 공유하며, 화면마다 별도의 색상·컴포넌트 체계를 만들지 않습니다.

[추가 화면 시안](../design-system/sample/screens.html)에서 발급 결과·강화 확인·질문 묶음 인박스와 설정·오류·빈 상태를 확인할 수 있습니다. 카드 자리표시자는 2:3 SVG이며 최종 카드 아트가 아닙니다. 시안의 버튼은 실제 기능과 연결되지 않습니다.

## 공통 화면 규칙

- 모바일을 우선하고 현재 390px 시안을 출발점으로 좁은 화면과 넓은 화면에서도 가로 스크롤 없이 콘텐츠가 읽히게 합니다. 하단 탐색과 고정 입력창이 콘텐츠·포커스를 가리지 않도록 여백과 안전 영역을 확보합니다.
- 의미 토큰을 사용해 화면 배경·표면·본문·보조 텍스트·버튼·테두리·오류를 구분합니다. 본문과 입력은 16px, 보조 텍스트는 최소 12px을 기준으로 하고 실제 대비와 확대 시 가독성을 확인합니다.
- 버튼·탭·필터 등은 44px 이상의 조작 영역과 보이는 포커스를 제공하고, 색상 외 텍스트나 아이콘으로 상태를 구분합니다. 아이콘만 있는 버튼에는 접근 가능한 이름을 제공합니다.
- 버튼은 기본·누름·비활성·처리 중, 입력은 기본·포커스·오류 상태를 표시합니다. 로딩·빈 목록·오류·권한 없음은 구분하고 가능한 경우 재시도나 다음 행동을 제공합니다. 입력 오류는 해당 입력 가까이에 표시합니다.
- 아이콘은 디자인 시스템의 일관된 SVG 규칙을 사용합니다. 이미지에 필요한 대체 텍스트를 제공하고, 장식용 이미지는 보조 기술에서 숨깁니다. `prefers-reduced-motion`을 존중합니다.

## 카드 중심 시각 체계

**카드 기반 디자인 시스템 (2026-11-13):** 실제 카드 아트의 언어를 앱 디자인 시스템에 옮겼습니다. 아이보리 바탕, 딥그린 사선, 세로 압축 영문 이름, `AFFILIATION`·`— LEVEL —` 라벨, 평행사변형 등급 태그가 해당합니다. 톤은 스포츠 에디토리얼 라이트입니다. 등급색은 BASIC 그린·RARE 레드·LEGEND 블랙+골드입니다. 컴포넌트 라이브러리는 도입하지 않고 토큰 3층(원시 스케일→의미→등급)과 `card.css` 패턴으로 구성했습니다. 1차 적용은 카드 화면이며, 다른 화면은 [에이전트 가이드](../design-system/AGENT_GUIDE.md)의 2차 인계 표를 따릅니다. 토큰·마크업은 [개발 적용 가이드](../design-system/DEVELOPMENT.md)를 참고합니다.

딥그린·아이보리와 굵은 제목으로 카드 아트와 앱을 연결합니다. 사선은 주요 배너에만 사용하고 골드는 희소성 표시에 한정합니다. 홈의 공태풍 카드는 사용자 제공 디자인 미리보기이며 실제 보유·발급 결과가 아닙니다. 앱 카드의 등급은 이미지 밖에 표시해 원본 아트를 가리지 않습니다. 홈의 대표 카드는 확대·기울기·그림자로 전시하고, 배너에 낮은 대비의 코스 등고선을 적용합니다. 수집 현황은 큰 숫자와 밝은 패널로 강조하며 카드 그리드에는 얕은 그림자를 사용합니다. 미보유 카드에는 그림자를 사용하지 않습니다. 카드 미리보기 링크는 컬렉션으로 이동하며, 호버·누름 반응은 동작 줄이기 설정을 존중합니다. 서비스 등급과 발급 동작은 유지합니다.

## 카드와 발급 결과

- 카드 디자인은 **별도 프로젝트**로 진행합니다. 이 저장소는 그 결과를 앱에 표시하고 연동하는 역할이며, 별도 프로젝트의 위치·일정·전달 방법은 아직 정해지지 않았습니다.
- 카드의 기본 가로:세로 비율은 **2:3**입니다. 앱의 카드 표시 영역과 자리표시자도 이 비율을 기준으로 공간을 확보합니다. 실제 해상도, 안전 여백, 프레임·아트 분리 및 파일 전달 규격은 별도 프로젝트에서 확정합니다.
- 현재 로컬 30개 WebP는 자리표시자입니다. 최종 산출물은 스타일 구분 없는 4유형·3등급의 실제 제작 목록을 기준으로 하며, 최종 개수·식별자·등급별 이미지 매핑과 Storage 연결은 담당자 간 확인합니다. path·파일명은 `<유형>-<선수명>-<레벨>.png`로 확정되어 있으며 이전 스타일 기반 WebP 경로로 되돌리지 않습니다. 이미지 로드 실패 시에도 이름·등급·수량을 확인할 수 있어야 합니다.
- **카드 뽑기 연출**은 2026-11-13 목업 시안(`/draw/preview`)으로 확정했습니다(`/draw` 적용은 새 3등급 SDK 뒤). 시안은 뒷면 카드가 두근두근 뛰다가 탭하면 3D로 뒤집히는 방식입니다. 등급이 높을수록 박동이 길어지고 빛이 강해지며, 건너뛰기·동작 줄이기를 지원합니다. 스타일은 `card.css`의 `.bb-draw-*`, 시간은 `drawRevealTiming`입니다. 실제 `/draw`는 확정된 서버 결과 화면과 요청 상태를 유지합니다.
- 서버에서 발급을 확정하며 화면 이탈이나 향후 연출 선택이 결과를 바꾸지 않습니다. 중복 요청 방지와 결과 미확정 복구는 [현호P 계획](./현호P_plan.md)을 따릅니다.

## 카드 목록 UI — API 연결 제외

사용자의 후속 지시에 따라 이번 목록 개선에는 API 연결을 포함하지 않습니다. 2026-11-13 결정으로 컬렉션과 보유 카드를 별도 화면으로 나눴습니다. 기존 `/collection?tab=owned`는 보유 경로로 이동합니다.

- **컬렉션(`/collection`)**: API와 무관한 정적 도감입니다. manifest의 선수×등급 카드 36장을 실제 아트로 전시하고, 미보유는 흑백과 "미보유" 텍스트로 표시합니다. 등급·유형 칩으로 거릅니다. 수집 현황(모은 카드 n/36, 선수 n/12, 등급별)은 보유 데이터를 겹쳐 계산하며, 보유 조회가 실패해도 목록은 유지합니다.
- **보유 카드(`/collection/owned`)**: 양수 수량의 선수·등급 조합만 표시합니다. 같은 선수의 BASIC과 RARE를 합치지 않습니다. 등급·유형 칩, 선수 선택(보유 선수만), 등급순(기본)·장수순 정렬 토글과 보유 현황 패널을 제공합니다.
- 필터는 입력 폼처럼 보이는 select 그리드 대신 디자인 시스템 칩·정렬 토글·현황 패널을 씁니다. 등급 칩은 카드의 LEVEL 태그처럼 평행사변형·등급색입니다.
- 강화 가능한 조합에 보유 목록의 강화 미리보기 링크를 제공하고, 상세·강화에 선택 등급을 전달하며 보유 목록 복귀를 유지합니다.
- 보유 카드 없음(라운드 진입), 필터 결과 없음(조건 초기화), 등록 카드 없음, 로딩·오류·재시도 표시를 분리했습니다. 로딩·오류는 표시 구성만 준비했으며 네트워크를 시뮬레이션하지 않습니다.
- 보유 수량·수집 현황·강화 비용은 목업임을 화면에 명시합니다. 선수명은 제공된 slug를 사용하고 확인된 공태풍만 한글로 표기합니다. 인물 UUID나 미확정 표시명을 추측하지 않으며, 실제 SDK의 4등급을 임의로 변환하지 않습니다.

## 카드 상세 UI

`/collection/[cardId]`는 공통 목업 카드 이미지(R2 `default-card-at.png`)를 크게 표시하는 목업 상세 페이지입니다. 같은 카드의 BASIC·RARE·LEGEND 전환과 등급별 수량, 0장 등급의 미보유 표시를 제공합니다. `/collection/c1` 등으로 접근하거나 홈·컬렉션의 카드 링크를 사용합니다. 2:3 디폴트 이미지, 이름·유형·등급·장수, 근거가 있는 경우의 인증 배지, 강화 부족 수량·최고 등급 안내를 제공합니다. 보유 탭에서의 진입은 같은 탭으로 돌아갑니다. 존재하지 않는 카드에는 카드 없음 화면을 표시합니다.

이번 단계에서는 사용자 요청에 따라 실제 아트·CDN·DB를 연결하지 않습니다. 시안 기준 비용은 10장이며 수량이 충분한 카드 상세에서 강화 미리보기로 진입합니다. 실제 API 연결·설정 비용과 수량 갱신은 후속 작업입니다. 목록·홈의 공용 카드 목업도 스타일 없는 3등급으로 갱신했으며 기존 서버 등급 변환은 하지 않습니다.

## 강화 확인·결과 UI

`/collection/upgrade?cardId=c2`는 디폴트 카드로 강화 전후와 소모·획득·잔여 수량을 표시하는 목업입니다. BASIC 예시 카드 c2는 11장으로 준비했습니다. 수량 확인 체크 후 결과를 미리 볼 수 있고, BASIC → RARE → LEGEND 순으로 표시합니다. 부족 수량·최고 등급으로 직접 진입해도 결과 확인은 차단합니다.

결과는 컴포넌트 내부의 일시적인 계산 예시이며 DB·CDN·강화 API·수량 변경·저장은 없습니다. 확인 후 카드가 모여 다음 등급이 공개되는 기본 강화 연출(RARE 약 3초·LEGEND 약 5초 시안)을 거쳐 결과로 전환하며 결과 제목으로 포커스를 이동합니다. 건너뛰기를 제공하고 동작 줄이기 설정에서는 연출 없이 결과를 표시합니다. 돌아가거나 새로고침하면 초기 목업을 사용합니다. `from=owned`는 상세·컬렉션 복귀에도 유지합니다. 실제 강화 연출·멱등 요청·오류 복구는 후속 SDK 연결 범위입니다.

## 공통 상태·프로필 샘플

[로딩·오류·프로필 시안](../design-system/sample/states.html)에 로딩 스피너, 버튼 처리 중, 연결 오류, 404와 기본 프로필을 추가했습니다. 스타일은 `states.css`로 공유하고 기본 프로필 SVG는 `public/assets/avatar-default.svg`를 단일 원본으로 사용합니다. 동작 줄이기와 안내 텍스트를 지원합니다. 현재는 샘플 단계이며 앱의 Spinner·Avatar와 실제 오류·404 라우트는 기존 동작을 유지합니다.

## 구현과 검증

현재 프로젝트 루트의 홈·컬렉션·발급은 목업이고 채팅 등은 더미 SDK를 사용합니다. 기존 공통 셸과 토큰을 재사용해 화면을 보완하고, 실제 SDK·Auth 연결 여부를 목업과 구분해 기록합니다. 원본 디자인 시스템과 앱 사본의 차이를 확인한 뒤 필요한 공통 컴포넌트를 적용합니다.

구현 시 모바일과 넓은 화면, 긴 이름·텍스트 확대, 키보드 포커스, 텍스트 대비, 로딩·빈 상태·오류, 이미지 실패 및 동작 줄이기를 확인합니다. 실제 데이터 연결과 화면 동작은 각각 검증하며, 실행하지 않은 항목은 완료로 표시하지 않습니다.
