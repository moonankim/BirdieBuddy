### 2.1 C-1 카드 실제 데이터 기준 (현호P 확정 사항)

- 컬렉션 `/collection`: 지금은 manifest 정적 도감. 새 `getCollection`이 나오면 카드 목록 원본을 API로 바꾸고, 조회 실패는 오류·다시 시도로 보여 준다(manifest로 대체하지 않음).
- 보유 카드·상세·강화: `getOwnedCards` 계열에서 같은 선수 행을 모아 구성. 상세는 보유한 카드만, 0장 등급·없는 카드는 `/collection/owned`로 이동.
- 강화는 `upgradeCard`(같은 요청 ID 재시도) 성공 뒤 연출·수량 갱신.
- 카드 이름은 `docs/card-assets.md` "선수 한글 표시명" 표를 쓴다(slug 자동 변환 금지).
- 연결 지점은 `card-ui-handoff.md` "API 연결 시 교체 지점"·"카드 상세 규칙"·"컬렉션 API 전환".

### 2.2 H-1 발급 결과·뽑기 연출 기준

- `completeRound` 결과를 `CardDrawReveal`(card+imageUrl, isNew, ownedCount, entryUnlocked)에 넘긴다.
- **처음 도착했을 때만 연출**하고, 새로고침·재진입은 결과만 보여 준다(공개 완료 표시는 계정별 발급 결과 키와 같은 규칙으로 저장·삭제).
- 연출·건너뛰기·이탈은 새 발급을 하지 않는다. 적용하면 `PreviewLink`와 `/draw/preview`를 지운다.
- 보유 배지 3종과 입장 조건(누적 5장)은 그대로라 화면 변경 없음(문환P·현호P 합의 규칙).

문환P가 서비스 소개 문서(`docs/service-overview.md`)에서 자성P를 **팀 대표**로 지정해 남긴 요청이다. 코드 작업은 아니다.
