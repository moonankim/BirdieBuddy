# BirdieBuddy AI 프로세스 설계

작성일 2026-11-09 · 원본 기획: `spec_BirdieBuddy.md` (Nov 6, 2026) · 시험 코드: `lib/ai/tests/`

표기: **[결정]** 사용자가 정한 것, **[제안]** 작성자 판단으로 사용자가 아직 확정하지 않은 것, **[미정]** 사용자가 정해야 하는 것.

## 1. 목적

스크린골프 인플루언서 카드 서비스의 해커톤 시연에서, 채팅방 안에서 AI가 실제로 판단하는 세 기능을 만든다.

1. 메시지 안전 필터: 유저가 보내기 전에 부적절한 메시지를 걸러내고 사유를 안내한다.
2. 대화 요약: 인플루언서가 긴 대화를 빠르게 훑어본다.
3. 유사 질문 묶기: 비슷한 질문을 대표 질문 하나로 묶고 질문한 인원수를 표시한다.

인플루언서는 안심하고 채팅방을 쓰고, 한 번 답해 여러 명에게 답하는 효과를 얻는 것이 이 기능들의 가치다.

## 2. 범위

**[결정] 포함:** 위 세 기능. 역할 분담에서 "AI가 실제로 판단하는 곳"이 이 설계의 담당이다.

**제외:** 카드 뽑기, 강화, 컬렉션, 채팅방 입장과 게이지, 관리자 승인 화면 등 화면과 규칙 로직은 다른 담당자 몫이다. 카드 교환, 레전드, 초상권 검토는 원본 기획에서 제외돼 있다.

**[정리됨] 추가 담당 AI 기능:** 메시지 품질 점수(A-03)와 카드 이미지 생성(A-06)도 `architecture.md`상 문환P 담당이다. 이번 시험에서는 다루지 않았다. 우선순위 계산 공식은 `lib/scoring.ts`로 홍주P 담당이다.

**안 되는 것(이렇게 되면 실패):**
- AI 모델이 차단 여부를 최종 결정한다. 항상 차단 항목이 해제되거나 낮춰지면 안 된다.
- API 키가 웹뷰 등 클라이언트에 노출된다.
- 시험 코드(`lib/ai/tests/`)를 그대로 본 구현으로 옮긴다.
- 실존 인물과 실제 팬 메시지를 시험 데이터로 쓴다.

## 3. 제약

- 기술 스택과 팀 연동은 `docs/architecture.md`를 따른다(Next.js App Router, TypeScript, API Route). 이 문서와 어긋나면 사용자가 이 문서에서 **[결정]**으로 정한 항목을 제외하고 `architecture.md`가 우선한다.
- **[결정]** AI 호출은 서버 측 TypeScript 모듈 `lib/ai`에 두고, 화면은 서버 API로 호출한다. 키를 클라이언트에 둘 수 없어서다.
- 환경변수: `ANTHROPIC_API_KEY`, `TYPESAFE_API_KEY`.
- 메시지 원문이 외부 AI 서비스(Anthropic, TypeSafe)로 전송된다. 시연 전 사내 정책 확인이 필요하다.

## 3-1. `lib/ai` 구성과 시험 환경

**[결정]**
- 이번 환경구성의 범위는 `lib/ai` 작업에 필요한 만큼이다. Next.js 골격(F-01), Supabase(B-01), 배포(B-11)는 다른 담당자 몫이라 포함하지 않는다.
- 시험 페이지는 `lib/ai/tests/`에 두고, 호출 코드는 `lib/ai/`로 빼서 화면은 그 함수를 호출하는 시험 화면으로 쓴다.
- 메시지 필터는 Jev, 수정 문장과 대화 요약은 Claude API를 쓴다.
- `moderateAndScore`의 형식은 아래 4절의 혼합 형식이다.
- 이번에 실제로 구현하는 것은 필터, 수정 문장, 품질 점수, 금칙어 폴백이다. 요약과 묶기는 `lib/ai/tests/server.ts`에 그대로 두고 시험 화면도 계속 동작시키며, `lib/ai/index.ts`에는 `architecture.md` 시그니처의 스텁만 둔다(A-01). 두 시그니처는 10절 8번의 미정 항목이다.
- 문서는 모든 시험과 결정이 끝난 뒤 `docs/문환P_plan.md`만 고친다. `architecture.md`와 다른 담당자의 plan 파일은 고치지 않고, 다른 담당자의 에이전트가 알아야 할 변경(인터페이스, API 추가, B-06·F-06 영향)은 커밋 메시지에 남긴다.

**작성자 판단 (사용자 미확정)**
- `package.json`은 `lib/ai/tests/`에서 `lib/ai/`로 올린다. Node는 `lib/ai/*.ts`의 패키지를 위쪽 폴더에서 찾으므로 `tests/node_modules`를 쓸 수 없다. 최상위 `package.json`을 만들지 않아 F-01과 겹치지 않고, 통합할 때 `@anthropic-ai/sdk`를 최상위 의존성으로 옮긴다.
- API 키는 `lib/ai/tests/.env`에 두고 커밋하지 않는다. 시험 서버는 `127.0.0.1`에서만 띄운다.
- `disabledFilters`와 `category`의 값은 영문 key(`profanity` 등)다. 화면 표시는 `flagged`의 `label`로 한다. `architecture.md`의 주석 예시도 맞춰 고친다.
- `lib/ai/`의 코드는 Node 직접 실행(시험 서버)과 Next.js 번들(실제 API) 양쪽에서 동작해야 한다. import 확장자와 JSON 로드 방식은 builder가 정한다.
- `lib/ai/tests/`는 F-01 이후 Next.js 타입 검사에서 제외해야 한다. 자성P에게 전달한다.

## 4. 기능 1: 메시지 안전 필터

**[결정] 구조:** Jev가 항목별 확률만 판단하고, 처리 방식은 코드 규칙이 정하고, 안내 문구는 Claude로 미리 만들어 저장한 것을 쓴다. Jev를 쓰는 이유는 속도다.

### 처리 흐름

1. Jev에 메시지를 보내 아래 10개 항목의 `noul`(0~1 확률)을 한 요청으로 받는다.
2. 확률이 기준값 이상인 항목을 위반으로 본다. **[결정 기반 제안]** 기준값은 전 항목 0.5.
3. 코드 규칙으로 처리 방식을 정한다.
   - 항상 차단 항목이 하나라도 있으면 `block`
   - 선택 항목만 있으면 `suggest_edit`
   - 없으면 `pass`
4. 위반 항목 중 항상 차단 항목을 우선하고, 그 안에서 확률이 높은 항목의 저장 문구를 응답한다.
5. **[결정]** `suggest_edit`일 때만 Haiku 5.5가 그 메시지를 고친 문장을 만들어, 저장 문구 뒤에 비동기로 덧붙인다. 유저에게 제안만 하고 메시지를 자동으로 바꾸지 않는다. 수정 문장은 판정 응답에 포함하지 않고 별도 함수와 별도 API로 받는다.

`suggest_edit`는 내부 판정 이름이고, `moderateAndScore`는 외부에 `suggest`로 돌려준다. DB의 `filter_verdict`와 값을 맞추기 위해서다.

Jev에게 "어떻게 처리할까"를 직접 묻지 않는다. 시험에서 Haiku가 직접 정한 처리 방식은 항상 차단 대상 5/24건을 낮춰 판정했지만, 같은 결과에 코드 규칙을 적용하면 놓침이 2/24건으로 줄었다.

### 항목

| key | 표시명 | 구분 | Jev 질문에 넣는 설명 |
|---|---|---|---|
| profanity | 욕설 | 선택 | 욕설이나 비속어. 사람을 향하지 않고 골프 샷을 설명하는 거친 은어는 포함하지 않는다 |
| belittling | 가벼운 비하 | 선택 | 상대를 깎아내리거나 조롱하는 표현 |
| hate | 혐오 표현 | 선택 | 성별, 지역, 출신, 장애 등 집단에 대한 혐오 |
| appearance | 외모 평가 | 선택 | 상대의 외모나 몸매를 평가하는 표현 |
| threat | 협박 | 항상 차단 | 해를 끼치겠다는 위협. 직접 말하지 않고 사고, 안전, 신변을 들먹이며 불안하게 만드는 암시나 돌려 말하는 경고도 포함한다 |
| stalking | 스토킹성 | 항상 차단 | 집요하게 따라다니거나 위치와 일상을 감시하는 내용. 공개되지 않은 동선, 차량, 옷차림, 집 주변을 직접 보았다거나 안다고 드러내는 내용, 사적인 공간에 몰래 접근했다는 내용도 포함한다 |
| sexual_harassment | 성희롱 | 항상 차단 | 성적인 언급이나 요구. 운동이나 골프 표현에 빗댄 성적 암시도 포함한다 |
| privacy | 사생활 침해 | 항상 차단 | 주소, 연락처, 가족 등 사적인 정보를 캐거나 공개하는 내용. 사는 곳을 안다고 드러내거나 수입, 연애사를 캐묻는 내용도 포함한다 |
| illegal_ad | 불법 광고·도박 | 항상 차단 | 불법 광고나 도박 홍보. 은어로 표현한 불법 약물 판매나 비밀 거래 유도도 포함한다 |
| spam | 스팸·도배 | 항상 차단 | 광고성 권유, 무의미한 내용을 복사해 붙인 도배, 같은 글자나 문구를 기계적으로 길게 반복하는 도배. 경기를 응원하는 짧은 구호나 감탄사를 몇 번 반복하는 것은 포함하지 않는다 |

Jev 질문 형식은 `이 메시지에 다음 내용이 포함되어 있는가: {설명}`이고, `state`는 `{context, message}`다.

### 안내 문구

`lib/ai/tests/data/filter-templates.json`에 항목별 `reason`과 `guide`(선택 항목만)가 있다. `generate-templates.ts`로 Haiku가 생성했고, 사람이 검수하지 않았다. 코드와 분리된 데이터로 두어 문구만 고칠 수 있게 한다.

### 응답 형식 [결정: 혼합 형식]

`architecture.md`의 이름과 값을 유지하고, 시험에서 얻은 `flagged`, `guide`를 더하며, 수정 문장만 분리한다.

```ts
export type Verdict = "pass" | "suggest" | "block";

type ModerationResult = {
  verdict: Verdict;
  category?: string; // flagged[0].key
  flagged: { key: string; label: string; scope: "선택" | "항상 차단"; score: number }[];
  reason?: string;
  guide?: string | null;
  quality: number; // 0~100
};

export async function moderateAndScore(input: { body: string; disabledFilters: string[] }): Promise<ModerationResult>;
export async function suggestRewrite(body: string, flagged: string[], disabledFilters: string[]): Promise<string | null>;
```

- `disabledFilters`는 선택 항목만 무시한다. 항상 차단 항목은 목록에 있어도 무시하지 않는다.
- `suggestRewrite`는 `flagged`에서 알려진 항목 key만 사용한다. 호출자가 보낸 값을 프롬프트에 그대로 넣지 않는다.
- `suggest` 응답의 호출 흐름: `moderateAndScore`로 사유와 안내를 먼저 보여 주고, 화면이 수정 문장 API를 따로 호출한다.

### 수정 문장 안전 처리 [결정]

- `flagged`에 `hate`가 있으면 Claude를 호출하지 않고 `null`을 돌려준다. 화면은 안내 문구만 보여 준다.
- 고친 문장은 Jev로 재검사한다. 재검사에는 같은 `disabledFilters`를 적용하고, 위반이 하나라도 있거나 재검사가 실패하면 `null`을 돌려준다.
- 재검사는 위반 여부만 본다. 비하가 칭찬으로 바뀌는 것처럼 뜻이 달라지는 문제는 막지 못하며, 이 한계는 받아들인다.

### Jev 실패와 지연 처리 [결정]

- Jev가 실패하거나 제한 시간을 넘기면 금칙어 폴백으로 판정한다(A-07). API 키가 없어도 필터가 동작해야 한다.
- 폴백은 `flagged`를 금칙어 일치 항목으로 채우고 같은 코드 규칙을 적용한다. 판정 값은 3개를 유지하며 판정 불가 상태는 두지 않는다. DB와 B-06은 바뀌지 않는다.
- 폴백의 `quality`는 50, `flagged[].score`는 1이다.
- 장애 중에는 금칙어에 없는 위반이 통과할 수 있으며, 이 위험은 받아들인다.
- 제한 시간 값과 금칙어 목록은 builder가 정한다. 첫 호출에서 3.8초가 측정된 적이 있으므로(1회), 제한 시간은 첫 연결 지연을 측정해 정한다.

### 품질 점수 [결정]

같은 Jev 요청에 `quality` 이름의 `type: "score"` 질문 하나를 추가한다. 응답 `score`는 0~4의 소수이고, `quality = score × 25`로 0~100에 맞춘다.

- `instructions`: `이 메시지가 인플루언서가 답할 가치가 얼마나 있는지 구체성과 답변 가치를 기준으로 평가한다.`
- `criteria` (레벨 0부터):
  0. 인사, 응원, 감탄처럼 답을 기대하지 않는 메시지
  1. 주제가 없거나 막연해서 답하기 어려운 질문
  2. 주제는 있지만 누구에게나 해당하는 일반적인 질문
  3. 자신의 상황이 일부 드러나 있어 구체적으로 답할 수 있는 질문
  4. 구체적인 상황, 수치, 시도한 내용이 담겨 있어 답변이 다른 팬에게도 도움이 되는 질문
- A-03의 "중복 여부"는 메시지 단건으로 판단할 수 없어 품질 점수에서 제외하고 유사 질문 묶기(A-04)에 맡긴다.
- 막연한 질문과 일반적인 질문은 구분이 약하고, 숫자와 용어를 나열하면 점수가 어느 정도 오른다. 시연 범위에서는 받아들인다.

### 팀원 영향 [결정의 결과]

- 홍주P: B-06은 `suggest`일 때 수정안 대신 `reason`, `guide`를 반환한다. 수정 문장 API를 1개 추가하고, 입장한 유저만 호출하며 글자 수를 제한한다. DB 스키마는 바뀌지 않는다.
- 자성P: F-06에 수정 문장 생성 중, 생성 실패(안내만 표시), 기다리는 사이 입력 변경(늦게 온 수정 문장 무시) 상태를 추가한다.
- 전달 방식: 위 영향은 `docs/문환P_plan.md` 갱신 커밋의 메시지에 인터페이스, 추가 API, B-06·F-06 변경 사항을 적어 알린다.

### 원본 기획에 있지만 시험 코드에 없는 것

- 인플루언서별 선택 필터 해제: 코드 규칙에서 해제된 선택 항목을 무시하면 된다. 항상 차단 항목은 설정으로 끌 수 없어야 한다.
- 입장 시와 필터 해제 방의 안내 메시지, 필터가 N건 걸렀다는 요약.
- 위반 반복 시 제재. 횟수와 기간은 원본 기획에도 없다.

## 5. 기능 2: 대화 요약

**[결정]** Claude Haiku 5.5, 스트리밍, Jev 미사용.

- 입력: 채팅방 메시지(시험은 300개, `[시각] 닉네임: 내용`).
- 설정: `output_config: {effort: "low", format: json_schema}`, `max_tokens` 8000.
- 출력: `overview`(2~3문장), `mood`(1문장), `topics[{title, summary, approx_messages}]`(최대 8개), `questions_to_answer[{question, approx_askers}]`(최대 8개). 프롬프트는 `server.ts`의 `summarize` 참고.
- 화면은 스트리밍 중에 완성된 필드부터 표시한다. 시험 코드는 SDK 내부 경로의 부분 JSON 파서(`@anthropic-ai/sdk/_vendor/partial-json-parser/parser`)를 쓰므로, 본 구현에서는 대체 방안을 builder가 정한다.
- `approx_messages`, `approx_askers`는 모델 추정치다. 정확한 숫자처럼 표시하지 않는다.
- **주의:** 요약에서 Haiku의 간헐적 사고 단계 영향은 측정하지 않았다. 질문 묶기처럼 끄는 것이 나은지 확인이 필요하다.

## 6. 기능 3: 유사 질문 묶기

**[결정]** 요약과 분리된 기능, Claude Haiku 5.5 단독, `thinking: {type: "disabled"}`, Jev 미사용.

- 입력: 각 메시지 앞에 `#번호`를 붙여 전달한다.
- 출력: `groups[{representative_question, message_ids}]`. 프롬프트는 `server.ts`의 `groupQuestions` 참고.
- **[제안]** 2건 이상 모인 질문만 표시한다.
- 인원수는 모델이 아니라 코드가 그룹의 고유 발신자로 계산한다. 인원수가 그대로 화면에 나가므로, 없는 번호와 중복 번호는 제외한다. **[제안]** 닉네임은 겹치거나 바뀔 수 있으므로 입력에 유저 고유 ID를 받아 그 값으로 센다. 시험 코드는 가상 닉네임으로 셌다.
- 답을 기대하지 않는 메시지가 섞이고, 실행할 때마다 그룹 구성이 달라진다. **[제안]** 시연에서 같은 화면을 재현하려면 결과를 고정해 둔다.

## 7. 시험 결과 (근거)

모두 실제 API, 시험 메시지는 AI 생성 또는 작성자 작성의 가상 데이터다. 품질은 사람이 일부를 읽어 본 수준이며, 실제 유저 메시지에서의 정확도는 모른다.

| 기능 | 방식 | 시간 | 근거 |
|---|---|---|---|
| 필터 | Jev + 코드 규칙 | 중앙값 0.17초, 최대 0.34초 | 60문장, 정확도 58/60, 정상 오탐 1/20, 항상 차단 놓침 1/24 |
| 필터 | Haiku + 코드 규칙 | 중앙값 1.16초, 최대 3.20초 | 60문장, 정확도 58/60, 정상 오탐 0/20, 항상 차단 놓침 2/24 |
| 필터 수정 문장 | Haiku | 중앙값 2.3초, 최대 3.2초 | 16문장, 재검사 통과 14/16 |
| 요약 | Haiku 스트리밍, 한도 8개 | 완료 6.1초, 첫 토큰 0.75초 | 3회. 페이지 첫 글자 1.2초 |
| 요약 | Haiku + Jev 화제 분류 병렬 | 14.4초 | 3회, 기각 |
| 질문 묶기 | Haiku 단독, 사고 끄기 | 3.3~6.7초 (미디어 프로 방) | 5회 |
| 질문 묶기 | Jev로 질문 선별 + Haiku | 8.9초 | 3회, 기각 |

기준값 0.5는 30문장으로 정하고 나머지 30문장으로 검증해 양쪽 모두 28/30이었다. 틀린 2건은 "화이팅!! 화이팅!!"(도배 오탐)과 "무슨 일 생겨도 책임 못 진다"(돌려 말하는 협박 놓침)다.

**확장 시험 (2026-11-09).** `lib/ai/tests/data/moderation-test-set.json`은 Gemini 4 Argon이 만든 가상 문장 300개다(품질 100, 위반 150, 함정 50). 기대 판정은 Gemini가 붙였고 사람이 검수하지 않았으며, 측정은 1회다. 절반(160문장)으로 항목 설명을 고치고 나머지 절반(140문장)으로 검증했다. 다만 수정 전에 300문장의 불일치 목록을 봤으므로 검증 절반도 완전히 독립적이지 않다.

| 지표 (검증 140문장) | 기존 설명 | 새 설명 |
|---|---|---|
| 기대 판정 일치 | 123 | 129 |
| 차단 대상 놓침 | 11 | 9 |
| 정상 문장 오탐 | 4 | 1 |

기존 60문장 시험은 새 설명으로 60/60이다. 품질 질문을 추가해도 필터 응답 시간(중앙값 174ms → 176ms)과 60문장의 판정은 달라지지 않았다. 품질 점수 평균은 인사 0.04, 막연 1.94, 일반 2.32, 구체 3.97(각 25문장)이며, 구체적인 질문은 인사말보다 모두 높았다. 남은 놓침은 대부분 돌려 말하는 협박, 스토킹, 성희롱이다. 시연 범위에서는 받아들이고, 실서비스라면 신고나 사람 검토가 필요하다.

**Jev를 요약과 묶기의 속도 개선 수단으로 쓰지 않는다.** 오래 걸리는 부분은 Claude가 글을 쓰는 시간이라서, 앞단에 분류를 넣으면 호출만 늘어 더 느려졌다.

## 8. 외부 API

**Jev** (공식 OpenAPI https://docs.typesafe.ai/api, 실호출로 동작 확인)
- `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer`, `Content-Type: application/json`. SDK 없이 fetch로 호출했다.
- 요청: `{model: "jev-latest", state, questions: {이름: {type: "noul", instructions}}}`. 실측 응답 모델은 `jev-1.14.0`.
- 응답: `{model, answers: {이름: {type: "noul", noul: 0~1}}, usage: {input_tokens, output_tokens}}`.
- 공식 지원 여부 미확인: 한국어, 요청당 질문 수 상한, 호출 제한(자료마다 다름).

**Claude** (`@anthropic-ai/sdk` 1.6.0으로 동작 확인)
- `claude-haiku-5-5`. 구조화 출력은 `output_config.format`의 `json_schema`.
- `stop_reason`이 `end_turn`이 아니면(거절 포함) 결과가 없는 경우로 처리한다.
- 프롬프트에서 유저 메시지는 검사나 요약의 대상으로 명시해, 메시지 안의 지시를 따르지 않게 한다.

시험 코드에서 재시도를 끈 것(`maxRetries: 0`)은 측정용이므로 본 구현의 재시도 정책은 builder가 정한다.

## 9. builder에게 맡기는 것

모듈과 파일 구조, 서버 API 경로와 프레임워크, 스트리밍 전송 방식, 재시도와 타임아웃, 로그와 관측, 시험 작성 방식. Jev 호출 제한에 걸릴 때의 재시도 동시성은 시연 접속 규모를 보고 정한다(필터는 메시지당 1회 호출이라 시연 규모에서는 문제가 되지 않을 것으로 본다).

## 10. 사용자에게 확인이 필요한 것

1. **[정리됨, 작성자 판단] `suggest`에서 유저는 원문을 그대로 보낼 수 없다.** B-06의 "suggest는 저장 없이 반환" 규칙을 따른다. 인플루언서별 해제 설정은 `moderateAndScore`의 `disabledFilters`로 받는다.
1-1. **[미정] 요약의 `questions_to_answer`와 질문 묶기를 한 화면에 함께 보여 줄지.** 한쪽은 모델 추정치, 다른 쪽은 코드 계산값이라 숫자가 어긋난다. **제안:** 요약 스키마에서 질문 항목을 빼고 묶기 결과를 쓴다. 이 경우 요약 출력도 짧아질 것으로 보이지만 미측정이다.
1-2. **[미정] 요약·묶기의 입력 계약.** 호출자가 메시지 배열을 넘기는지 서버가 조회하는지, 대상이 방 전체인지 마지막 방문 이후인지, 최대 몇 건까지인지. **제안:** 호출자가 `{id, userId, nickname, text, time}[]`을 넘기고, 시연은 300건 이내로 고정한다. 그 이상의 분할 정책은 시연 범위에서 제외한다.
1-3. **[미정] 서버 API 인증과 방 접근 권한.** 요약과 묶기는 인플루언서 전용, 필터는 입장한 팬이 호출한다고 추정했다. 누가 검증하는지 팀과 정해야 한다. 인증 없이 열리면 다른 방 대화가 유출되고 호출 비용이 발생한다. 본 구현에서 고위험 항목이다.
1-4. **[미정] 묶기에서 인플루언서가 이미 답한 질문을 뺄지.** 빼려면 입력에 발신자 역할과 답변 연결 정보가 필요하다. **제안:** 시연은 제외하지 않는다.
1-5. **[정리됨]** 필터 장애 처리는 4절의 금칙어 폴백으로 정했다.
2. **[정리됨]** 수정 문장 안전 처리는 4절대로 정했다. 근거: 혐오·비하는 고치면 뜻이 반대로 바뀌는 사례가 있었고(예: "외국인 선수들은 다 쫓아내야 함" → 함께 응원하자), 고친 문장 2/16건은 재검사에서 다시 걸렸다.
3. **[정리됨] 도배 판정.** "화이팅!! 화이팅!!" 오탐은 코드 보정 없이 4절의 `spam` 설명으로 줄였다. 시연 문장은 A-08에서 확인한다. 유저별 연속 메시지 도배는 메시지 단건 판정으로 잡을 수 없다.
4. **[미정] 요약과 묶기의 실행 시점.** 인플루언서가 열 때 실행(시연 기본 제안, 약 4~6초)할지, 미리 계산해 둘지. 미리 계산은 측정하지 않았다.
5. **[정리됨]** 메시지 품질 점수(A-03)와 카드 이미지 생성(A-06)은 `architecture.md`상 문환P 담당이다. 품질 점수 방식은 4절의 시험 결과로 정하고, 카드 이미지 방식은 미정이다.
6. **[미정] 시연 범위.** 일정과 팀 연동 방식은 `architecture.md`를 따른다.
7. **[미정] 원본 기획의 미정 항목 중 AI에 영향을 주는 것:** 오차단 재검토 버튼 포함 여부. 점수 반영 비율은 `architecture.md`의 `priority_weights`(보유 0.6 : 품질 0.4)를 따른다.
8. **[미정] 요약·묶기 시그니처.** `architecture.md`는 `summarize`가 문자열을, `clusterQuestion(roomId, body)`가 메시지 한 건의 `cluster_id`를 돌려주지만, 시험 코드는 구조화된 요약 스트리밍과 방 전체 일괄 묶기다. 두 기능을 구현하는 단계에서 정한다.
